# corpus-docs

Marketing + docs site for **Corpus** — `https://corpus.dvpuchades.com`.

Built with [Astro](https://astro.build) (static output), [Tailwind CSS](https://tailwindcss.com), and [Caddy](https://caddyserver.com) in a Docker container behind a Cloudflare Tunnel. Bilingual EN/ES, dark only, no analytics, no tracking, ~22 KB initial HTML on the home page.

## Local development

```sh
# 1. Install dependencies (first time only)
npm install

# 2. Start the dev server with hot reload
npm run dev
# → http://127.0.0.1:4321

# 3. Type-check
npm run check

# 4. Production build (also runs scripts/build-llms.mjs)
npm run build

# 5. Preview the built dist/ locally
npm run preview
```

## Editing content

Docs articles live under `src/content/docs/{en,es}/<section>/<slug>.md`. The frontmatter schema (in `src/content/config.ts`):

```yaml
---
title: ...
summary: ...           # one-paragraph; doubles as meta description and the doc footer summary
section: getting-started   # one of: getting-started, daily-use, training, health-signals, privacy, faq
order: 1
updated: 2026-05-05
draft: false               # optional; drafts are excluded from the build
---
```

To add a new article, drop the file in the right section folder for both locales. The sidebar, doc index, and `llms.txt` pick it up automatically.

The privacy policy lives in `src/content/privacy/{en,es}.md` and uses a separate schema with `version`, `effective`, `updated`.

## Production: Docker + Cloudflare Tunnel

Static output served by Caddy in a slim Alpine container. Caddy handles compression (zstd + gzip), cache headers, and the `try_files` routing for clean URLs.

### Build & run locally to verify

```sh
docker build -t corpus-site .
docker run --rm -p 8080:80 corpus-site
# → http://127.0.0.1:8080
```

### Deploy to your server

On the server, clone the repo once, then:

```sh
./scripts/deploy.sh
```

The script: `git pull` → `docker build` → stop old container → start new one bound to `127.0.0.1:8080`.

### Wire up the Cloudflare Tunnel

If `cloudflared` isn't installed yet:

```sh
# macOS
brew install cloudflared
# Linux
curl -L --output cloudflared.deb https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64.deb
sudo dpkg -i cloudflared.deb
```

Authenticate and create the tunnel:

```sh
cloudflared tunnel login
cloudflared tunnel create corpus-site
cloudflared tunnel route dns corpus-site corpus.dvpuchades.com
```

Tunnel config (typically `~/.cloudflared/config.yml`):

```yaml
tunnel: corpus-site
credentials-file: /home/<user>/.cloudflared/<tunnel-id>.json

ingress:
  - hostname: corpus.dvpuchades.com
    service: http://localhost:8080
  - service: http_status:404
```

Run as a service:

```sh
sudo cloudflared service install
sudo systemctl start cloudflared
sudo systemctl enable cloudflared
```

That's it. TLS is terminated at Cloudflare's edge; the tunnel handles cert issuance.

### Smoke test after deploy

```sh
curl -I https://corpus.dvpuchades.com/        # 200 + cf-ray header
curl -I https://corpus.dvpuchades.com/en/      # 200
curl -I https://corpus.dvpuchades.com/llms.txt # 200, text/plain
```

## SEO & LLM signals

- Static HTML for every page; no client-side rendering.
- `<title>`, meta description, canonical, and OG/Twitter cards on every page.
- `hreflang` alternates (`en`, `es`, `x-default`) on every page.
- `sitemap-index.xml` auto-generated with i18n alternates.
- `robots.txt` explicitly allows GPTBot, ClaudeBot, PerplexityBot, Google-Extended, CCBot.
- Per-page JSON-LD: `SoftwareApplication` + `Organization` on home, `Article` on docs, `FAQPage` on FAQ, `WebPage` on privacy, `WebSite` on docs index.
- `/llms.txt` and `/llms-full.txt` (per locale) regenerated on every build via `scripts/build-llms.mjs`.

## Design tokens

Defined in `src/styles/tokens.css` and exposed to Tailwind via the `bg-*`, `text-*`, `accent`, `success`, `warning`, `hairline` utilities. To rebrand, change the CSS variables — components reference the tokens, not the raw values.

## OG (social-share) images

Generated at build time by `scripts/build-og.mjs` using [satori](https://github.com/vercel/satori) + [@resvg/resvg-js](https://github.com/yisibl/resvg-js). One 1200×630 PNG per locale, written to `public/og/{en,es}.png`. Both files are gitignored — they regenerate from `scripts/build-og.mjs` whenever copy or tokens change.

To re-render without a full build: `node scripts/build-og.mjs`.

The script reads `assets/fonts/Inter-Regular.ttf` and `Inter-SemiBold.ttf` (committed). If you want to tweak the headline, eyebrow, or layout, edit the `COPY` and `card()` definitions at the top of the script.

## Alternative hosting

If running your own server ever stops being worth it, the same `dist/` works as-is on **Cloudflare Pages**, **Vercel**, or **Netlify** — connect the repo, set the build command to `npm run build`, and the publish dir to `dist`. Move the domain over and the site is live with no Docker, no tunnel, no maintenance. Kept available as an option, not currently in use.
